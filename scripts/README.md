# scripts/ — инструментарий сборки Evolution

> При любом изменении скриптов (новые флаги, новые файлы, удаление,
> смена ответственного за задачу) — обновить этот README. Он единственный
> источник правды о том, что тут лежит и чем запускать сборку.

## Активные скрипты

| Скрипт | Строк | Назначение | Запуск |
|---|---|---|---|
| `make_n.sh` | ~410 | **Основной драйвер сборки.** TUI, `source envsetup` + `lunch`, выбор кастомного ядра из `device/google/pixel-kernels/` (`-k`, список через `--ls-kernel`), экспорт релиза (`-r`). Корректно завершается и при `source`, и при прямом вызове | `. scripts/make_n.sh -b -d shiba -t user -k <ядро> -j 16` |
| `sync_tree.py` | ~1200 | **Умный синк дерева.** Сканирует локальные правки, делает снапшот (бэкап + unified-патчи + увод untracked в сторону), гоняет `repo sync`, накатывает патчи обратно. Режимы: `--smart` (глубокий скан), `--diff` (только слепок), `--change` (менеджер снапшотов), `--forcesync`, `--revert` (откат к HEAD со страховкой), `--except` (исключения) | `sync_tree.py [--smart] [-j N] [-y]` |
| `setup_env.py` | ~580 | **Подготовка хоста с нуля:** менеджеры пакетов (apt/dnf/pacman), системные лимиты, ccache, git-lfs, repo+git, окружение юзера. Идемпотентен (маркер готовности, `--force` для повтора) | `setup_env.py [--ccache-size 80G] [--force]` |
| `shallow_tree.sh` | ~240 | **Перевод дерева в shallow (`--depth 1`) без перезаливки.** Проблема: `.repo/project-objects` хранит полную историю всех проектов (~126 ГБ). Скрипт фиксирует `repo.depth=1` (будущие синки останутся shallow), затем по каждому проекту делает `fetch --depth 1` и чистит object store (repack/prune с union keep-refs расшаренных refs). Рабочие копии и индекс не трогает, проекты со staged-изменениями чистке объектов не подвергает (только fetch). Идемпотентен | из корня дерева: `scripts/shallow_tree.sh [-j N] [-y]` |
| `lite_make.sh` | ~60 | **Точечная сборка отдельных soong-модулей** без полного ROM (синтаксис lunch как в `make_n.sh`) | `lite_make.sh [-d shiba] <модуль> [модуль…]` |
| `kill_soong.py` | ~270 | **Глушилка сборки.** Бьёт процессы Soong/Ninja, удаляет **только** `.lock`-файлы — кэши (`.ninja_*`, kati, `build.ninja`) не трогает, следующий запуск без долгого ре-анализа. Есть `--dry-run` | `kill_soong.py [-o ./out] [--dry-run]` |
